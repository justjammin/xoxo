What is XOXO?

XOXO is a local evaluation harness that compares any two models running on headless Claude Code or Codex—same framework or cross-framework—against the same task, keeps every receipt, and determines which candidate actually earned the crown.

Quick start

You can't sit with us—yet.

You need Bun 1.2+ and authenticated claude and codex CLIs sitting pretty on your PATH.

Terminal / the invitation
bun install
bun run xoxo init
bun run xoxo doctor
bun run xoxo compare examples/smoke.yaml \
  --x claude:claude-sonnet-4-6 --x-effort high \
  --y codex:gpt-5.6-sol --y-effort high
bun run xoxo dev

This example crosses frameworks, but X and Y can each use Claude Code or Codex independently. Sneak a peek at 127.0.0.1:5173 after running dev. The server stays on loopback by default—we do love our privacy.

Answer desk

Questions everyone is whispering.

Clear answers for humans, search engines, and the machines reading over their shoulders.

What is XOXO?

XOXO is a local evaluation harness that compares any two models running on headless Claude Code or Codex against the same isolated fixtures, records normalized and redacted evidence, applies deterministic assertions, and can use a blind third model for semantic judging.

How does XOXO compare any two models fairly?

Each candidate independently selects Claude Code or Codex, then receives the same prompt and a fresh copy of the same fixture. XOXO grades both with the same deterministic assertions before any semantic judge is allowed to vote.

Does XOXO support subagents?

Yes. Configure subagent model, effort, skills, and concurrency. Claude also supports per-agent max turns and spawn depth; XOXO rejects those controls for Codex because Codex does not document equivalents.

How does blind judging work?

Blind judging runs only after both candidates pass deterministic gates. XOXO assigns seeded A/B labels, asks a third model to apply the visible rubric, and maps the verdict back to X or Y.

Is XOXO safe for untrusted code?

XOXO uses native provider restrictions and isolated fixture copies, but toxic code belongs in an external container or VM. Authentication material stays out of reports and configured secrets are redacted.

Security

Dirty laundry stays hidden.

Runs operate inside native provider restrictions with pristine fixture copies—so if your code is toxic, run it in an external container or VM. XOXO never leaks authentication secrets into reports, refuses sketchy shell command strings from suite data, and redacts your dirty little secrets before anyone else can catch a glimpse.
